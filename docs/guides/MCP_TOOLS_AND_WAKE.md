# MCP 工具、私有协议与事件唤醒

控制台分开管理 **人格提示词**、**仿真提示词**、**事件与定时唤醒**。**MCP 工具管理** 负责工具开关、动作、参数及工具组私有协议，不再包含唤醒规则。

## 工具与动作

- **基础工具**：桥接自己的读消息、发送、记忆、表情、等待等能力；同一个开关可能控制多个工具。
- **独立工具**：如 `qq_get_group_profile`，用少量语义参数选择对应动作。
- **组合工具**：如 `qq_group_admin_invoke`，通过 `action` 和 `params` 调用该组已开启的动作。
- **动作**：SnowLuma 的底层 API。扩展组和具体动作须同时开启；永久排除或尚未映射的动作不能在页面中开启。

模型看到的参数 schema、控制台参数表与实际调用使用同一份工具定义。独立工具也支持 `params` 补充原生参数；外层语义参数覆盖同名原生参数。多动作工具可传 `action` 明确选择已开启的动作。

所有扩展调用统一经过桥接：令牌、模式、会话范围、官方参数 schema、出站审计与限频依次校验。需要的 `group_id` / 私聊 `user_id` 由会话补齐，显式填写的跨会话目标仍会被拒绝。

参数详情里默认勾选 **只校验，不调用 QQ 接口**。取消后会真的执行动作；写操作需在页面确认。

工具开关保存后立即影响调用权限。新增工具或动作的 schema 在 **重启 DSH** 后刷新；控制台展示的是配置状态。`qq_get_prompt.enabledTools` 会列出基础工具和已配置的扩展工具。

## 全局提示词与工具私有提示词

仿真层管理 AI 如何参与群聊、如何调用工具；人格层管理 AI 是谁、什么性格、怎么说话。实际组装顺序是 **仿真提示词 → 人格提示词 → 本轮任务与消息**：全局行为由 DSH preset 提供，桥接补上活跃工具组协议，再注入当前模式筛选后的人格全文，最后加入任务与消息快照。

全局安全规则和通用行为保存在 `dsh/agent-presets/qq-chat-v2/agent.cordis.yml` 的 `persona.prefix`，通过独立的「仿真提示词」页直接编辑。编辑框默认读取当前已有的预设内容；一代和二代各自独立。保存会自动备份并使用安装脚本的同一生成器，同步更新 DSH 实际读取的 `plugins/qq-agent-presets/presets/qq-chat-v2.patch.yml`；还原时也同步更新。旧 `.agent-presets/` 目录不再作为写入目标。仿真层修改后重启 DSH 生效。

人格在「人格提示词」页编辑，保存即影响下一轮，无需重启。唤醒场景文案在「事件与定时唤醒」页编辑，同样保存即影响下一轮。

仿真提示词页还可批量勾选注入的工具组协议，支持全选、清空和恢复已保存选择。它与工具页「注入此组提示词」使用同一份状态，保留各组原文，也不更改工具本身的开关；只有被选择且存在可用工具的组才实际注入。该选择保存后下一轮生效，无需重启 DSH。一代提示词仍是独立的整体预设，工具组选择用于二代。

工具协议分放在 `prompts/tools/<组名>.md`。原有的发送、读消息、水位、等待与收尾、记忆、人物档案、黑话、表情、语音等协议已经移入对应模块。

桥接在每次唤醒和 `qq_get_prompt.toolSuites` 中，按当前可用工具组内联私有协议：

1. 基础工具至少有一个可用，或扩展组内至少有一个动作开启，才算活跃组。
2. 私有提示词的独立注入开关也须开启。
3. 不活跃组的协议不会注入。语音/表情的功能总开关也参与判定。

控制台「私有提示词」可覆盖文本、关闭注入或把默认模块内容恢复到编辑框。每组最多 8000 字符，总注入上限 32000 字符。保存即影响下一次提示词生成。旧版备注自动补上抽离的协议，管理员自定义备注会保留；新格式保存后直接使用编辑内容。

运行时覆盖存放在 `state/tool-prompts.json`，不进 Git；模块默认值随代码版本管理。修改全局 preset 后运行 `node scripts/build-agent-preset-patches.mjs` 并重启 DSH。

## 独立的事件与定时唤醒

页面分为现有唤醒文案、自定义规则、现有唤醒参数与状态。消息、回复检查、有限睡眠到期、主动机会、拍一拍及首次接入的默认文案，逐字沿用重构前的代码，统一保存在 `src/wake-prompts.js`；编辑后覆盖当前场景，不改变原有触发算法。

「新增事件唤醒 / 新增定时任务」支持：

- 从白名单选择一个或多个目标会话。不关联工具，也不以任何工具开关作为触发条件。
- 单独开启收到消息唤醒，并选择成员变更、禁言、撤回、文件上传、好友/加群申请、账号状态、生命周期、心跳等上游事件。
- 设置定时间隔：0 表示关闭；最短 1 分钟，最长 30 天。
- 设置同一规则对同一会话的冷却时间，避免事件洪峰反复唤醒。
- 设置事件快照条数：0～100，0 不附加历史。新规则默认 10 条，旧规则默认 1 条。快照在实际投递时按当前会话与规则事件类型选取最近记录，按时间顺序提供；冷却和合批期间的新事件也能进入快照。纯定时任务可附带本会话近期各类事件。
- 编写本规则提示词，可用 `{{key}}`、`{{reason}}`、`{{time}}`、`{{event}}`。
- 每条规则可独立勾选注入的工具组提示词，默认全选，也可清空。选择随规则保存；只影响这条规则参与的唤醒回合，不改全局选择、协议正文或工具开关。尚无可用工具的组不注入；多条规则同时参与同一回合时合并所选协议，`qq_get_prompt.toolSuites` 与实际内联结果一致。未配置此字段的旧规则也按全选处理。
- 可选注入「消息回复」「随机搭话/主动机会」「事件处理」参考提示词，也可复制到编辑框自行改写。

新规则默认关闭。规则开启、目标仍获准、二代 AI 正在运行时才触发。原有消息条件由 AI 当前唤醒配置决定，主动机会继续按安静阈值、随机间隔与概率运行；自定义规则复用它们的合并窗口、繁忙队列、频率限制和回合收尾。没有未读消息的事件/定时任务在繁忙后仍会补发，已关闭或修改的旧任务不会复活。

事件仅投递到该事件所属且在规则中列出的会话；没有会话归属的网关健康事件，仅投递到管理员明确选定的目标。载荷使用受限字段，不包含申请 flag、访问令牌或内部配置。事件数据不能改变权限规则。

事件历史只在内存保留启动后最近 2000 条准入记录；单次快照另受 12000 字符预算限制，完整记录不会从中截断，`includedCount` 与 `partial` 标明实际条数和是否省略。这个设置控制上游事件记录；聊天消息快照仍由下方已有的未读/最近消息参数管理。

定时任务从规则保存或桥接启动后开始计时，暂停期间不补跑，恢复后重新计时。保存其他规则或场景提示词不会重置未改规则的计时和冷却。页面显示下一次定时检查时间。移出白名单后停止触发。

配置和唤醒场景覆盖保存在 `state/wake-rules.json`，不进 Git；兼容读取原 `state/tool-automations.json`，自动去掉工具关联，下一次保存时写入新格式。唤醒参数通过独立的「保存唤醒参数」按钮部分更新，不覆盖二代仿真页的发送和上下文草稿。

管理接口 `GET/POST /api/wake-rules` 仅允许控制台令牌；QQ 智能体令牌一律不能访问。可单独提交 `rules` 或 `prompts`，不必重新保存另一部分。

## 维护与验证

- `src/qq-tool-groups.js`：动作分组、工具归属、开关与参数映射。
- `src/mcp-tool-suites.js`：MCP 注册、schema 与调用适配。
- `src/tool-catalog.js`：官方目录参数校验与会话字段补齐。
- `src/tool-prompts.js` / `src/tool-protocols.js`：私有协议存储、迁移与注入。
- `src/wake-rules.js` / `src/wake-prompts.js`：独立的规则、调度和现有场景文案。
- `public/console-tools.js` / `.css`：管理界面。
- `public/console-wake.js` / `.css`：独立唤醒页面。

参数快照保留 198 个动作：基础参数取自已安装的 SnowLuma MCP 目录；1.14.22 新增的三项群分类标签参数对照本机运行时定义补齐。官方参考：[SnowLuma API](https://snowluma.github.io/zh/docs/api)。刷新脚本保留完整 schema，无法取得指定版本时不会静默降级；删除动作须显式使用 `--allow-removed`。

```sh
npm run test:tools
npm run test:audit
npm run test:mcp-servers
node scripts/build-agent-preset-patches.mjs --check
```

这些回归使用内存 MCP、临时状态与假网关。它们不会向真实 QQ 发消息。
