# MCP 工具、私有协议与事件唤醒

控制台分开管理 **人格提示词**、**仿真提示词**、**事件与定时唤醒**。**MCP 工具管理** 负责工具开关、动作、参数及工具组私有协议，不再包含唤醒规则。

## 工具与动作

- **基础工具**：桥接自己的读消息、发送、记忆、表情、等待等能力；同一个开关可能控制多个工具。
- **独立工具**：如 `qq_get_group_profile`，用少量语义参数选择对应动作。
- **组合工具**：如 `qq_group_admin_invoke`，通过 `action` 和 `params` 调用该组已开启的动作。
- **动作**：SnowLuma 的底层 API。扩展组和具体动作须同时开启；永久排除或尚未映射的动作不能在页面中开启。

模型看到的参数 schema、控制台参数表与实际调用使用同一份工具定义。独立工具也支持 `params` 补充原生参数；外层语义参数覆盖同名原生参数。多动作工具可传 `action` 明确选择已开启的动作。

所有扩展调用统一经过桥接：令牌、模式、会话范围、官方参数 schema、出站审计与限频依次校验。需要的 `group_id` / 私聊 `user_id` 由会话补齐，显式填写的跨会话目标仍会被拒绝。

参数详情里默认勾选 **只校验，不调用 QQ 接口**。取消后会真的执行动作；写操作需在页面确认。

工具开关保存后立即影响调用权限。新增工具或动作的 schema 在 **重启 DSH** 后刷新；控制台展示的是配置状态。`qq_get_prompt.enabledTools` 会列出基础工具和已配置的扩展工具。

黑话注入由 MCP「黑话与梗」组开关控制：只有该组开启（且 `slang.enabled` 未关闭）时，才向模型注入黑话表和【黑话】协议；组关闭时 `qq_get_prompt.slang.block` 为空、`qq_slang_query` / `qq_slang_submit` 返回 403，`enabledTools` 也不再列出它们，重启 DSH 后 MCP 侧连这两个工具都不会注册。自动提取候选与深度研究仍由 `slang.enabled` 控制，不受组开关影响。

`qq_get_cross_session_recent`（管理员私聊专用）：一次返回最近 N 小时**所有白名单会话**的近期消息摘要（每条 ≤120 字，默认 24h / 120 条 / 每会话 30 条），用于「空间更新」这类需要跨会话找话题的任务。仅 `private:<ownerQQ>` 且令牌匹配时可调用，其它会话一律 403；返回不含完整原文、媒体、申请 flag。摘要仍可能含聊天片段，只允许在管理员会话使用，不能转发或写进公开内容。可在「唤醒与状态」组关闭（flag `crossSessionRecent`）。

## 全局提示词与工具私有提示词

仿真层管理 AI 如何参与群聊、如何调用工具；人格层管理 AI 是谁、什么性格、怎么说话。实际组装顺序是 **仿真提示词 → 人格提示词 → 本轮任务与消息**：全局行为由 DSH preset 提供，桥接补上活跃工具组协议，再注入当前模式筛选后的人格全文，最后加入任务与消息快照。

全局安全规则和通用行为保存在 `dsh/agent-presets/qq-chat-v2/agent.cordis.yml` 的 `persona.prefix`，通过独立的「仿真提示词」页直接编辑。编辑框默认读取当前已有的预设内容；一代和二代各自独立。保存会自动备份并使用安装脚本的同一生成器，同步更新 DSH 实际读取的 `plugins/qq-agent-presets/presets/qq-chat-v2.patch.yml`；还原时也同步更新。旧 `.agent-presets/` 目录不再作为写入目标。仿真层修改后重启 DSH 生效。

人格在「人格提示词」页编辑，保存即影响下一轮，无需重启。唤醒场景文案在「事件与定时唤醒」页编辑，同样保存即影响下一轮。

仿真提示词页还可批量勾选注入的工具组协议，支持全选、清空和恢复已保存选择。它与工具页「注入此组提示词」使用同一份状态，保留各组原文，也不更改工具本身的开关；只有被选择且存在可用工具的组才实际注入。该选择用于普通唤醒和「沿用仿真页选择」的规则；规则切为自定义后，以规则自身的选择为准。该选择保存后下一轮生效，无需重启 DSH。一代提示词仍是独立的整体预设，工具组选择用于二代。

工具协议分放在 `prompts/tools/<组名>.md`。原有的发送、读消息、水位、等待与收尾、记忆、人物档案、黑话、表情、语音等协议已经移入对应模块。

桥接在每次唤醒和 `qq_get_prompt.toolSuites` 中，按当前可用工具组内联私有协议：

1. 基础工具至少有一个可用，或扩展组内至少有一个动作开启，才算活跃组。
2. 普通唤醒和沿用规则使用仿真页的注入开关；自定义规则使用本规则的工具提示词选择，覆盖仿真页勾选。
3. 不活跃组的协议不会注入。语音/表情的功能总开关也参与判定。

控制台「私有提示词」可覆盖文本、关闭注入或把默认模块内容恢复到编辑框。每组最多 8000 字符，总注入上限 32000 字符。保存即影响下一次提示词生成。旧版备注自动补上抽离的协议，管理员自定义备注会保留；新格式保存后直接使用编辑内容。

运行时覆盖存放在 `state/tool-prompts.json`，不进 Git；模块默认值随代码版本管理。修改全局 preset 后运行 `node scripts/build-agent-preset-patches.mjs` 并重启 DSH。

## 独立的事件与定时唤醒

页面分为现有唤醒文案、自定义规则、现有唤醒参数与状态。消息、回复检查、有限睡眠到期、主动机会、拍一拍及首次接入的默认文案，逐字沿用重构前的代码，统一保存在 `src/wake-prompts.js`；编辑后覆盖当前场景，不改变原有触发算法。

「新增事件唤醒 / 新增定时任务」支持：

- 目标会话由触发条件决定：消息、拍一拍、私聊撤回等会话事件需要选择一个或多个群/私聊目标；群成员、群禁言、群文件、群撤回等群事件只需要选择群（私聊目标不生效）；好友/加群申请、账号状态变化、网关生命周期/心跳以及定时任务不需要目标会话。
- 无目标会话的唤醒统一投递到管理员私聊会话：优先 `ownerQQ`，owner 不在私聊白名单时退回第一个可用的私聊白名单会话；两者都不存在时保存会被拒绝，避免留下永远不触发的规则。控制台会在目标区直接显示当前管理员会话。
- 申请类唤醒把事件里的 `flag` 一并交给模型。好友申请用 `qq_friend_invoke` 的 `set_friend_add_request`，加群/邀请申请同样用 `qq_friend_invoke` 的 `set_group_add_request`；`flag` 已限定申请目标，因此从管理员私聊会话调用时不要求 `group:` 会话 key。
- 不关联工具，也不以任何工具开关作为触发条件。
- 单独开启收到消息唤醒，并选择成员变更、禁言、撤回、文件上传、好友/加群申请、账号状态、生命周期、心跳等上游事件。
- 设置定时间隔：0 表示关闭；最短 1 分钟，最长 30 天。可再填「随机上限」形成 [下限, 上限] 分钟区间，每次触发后重新随机；上限为 0 或等于下限时按固定间隔。
- 设置同一规则对同一会话的冷却时间，避免事件洪峰反复唤醒。
- 设置事件快照条数：0～100，0 不附加历史。新规则默认 10 条，旧规则默认 1 条。快照在实际投递时按当前会话与规则事件类型选取最近记录，按时间顺序提供；冷却和合批期间的新事件也能进入快照。纯定时任务可附带本会话近期各类事件。
- 编写本规则提示词，可用 `{{key}}`、`{{reason}}`、`{{time}}`、`{{event}}`。
- 工具提示词默认「沿用仿真页选择」，单独编辑名称、事件、定时等参数不会变更此模式。自定义候选组初始全选；修改任意勾选、全选或清空会自动切换到「本规则自定义」，以规则选择为准，不再受仿真页勾选限制。清空表示本规则不注入工具协议，可随时切回沿用。模式和选择随规则保存，不改全局选择、协议正文或工具开关；尚无可用工具的组仍不注入。多条规则同时参与同一回合时，先按各自模式解析，再合并协议，`qq_get_prompt.toolSuites` 与实际内联结果一致。旧规则未配置选择或仍为默认全选时按沿用处理，已缩减或清空的旧选择保留为自定义；显式选择自定义全选后也不会变回沿用。
- 可选「允许主动找机会」：开启后，本轮除了处理触发的消息/事件，还可以在会话安静、没有待回应内容时主动开话题或追问上次没聊完的事；关闭（默认）时不额外注入主动指令，规则提示词保持原样，便于继续用自定义提示词控制。
- 可选注入「消息回复」「随机搭话/主动机会」「事件处理」参考提示词，也可复制到编辑框自行改写。

新规则默认关闭。规则开启、目标仍获准、二代 AI 正在运行时才触发。升级前保存的规则保留原有目标；申请类事件按新语义改投管理员会话，不再按申请人或目标群过滤（否则申请人不在白名单时永远不触发）。原有消息条件由 AI 当前唤醒配置决定，主动机会继续按安静阈值、随机间隔与概率运行；自定义规则复用它们的合并窗口、繁忙队列、频率限制和回合收尾。没有未读消息的事件/定时任务在繁忙后仍会补发，已关闭或修改的旧任务不会复活。

规则列表支持按名称/提示词/事件/目标搜索，并可按启用状态、触发方式（仅事件/仅定时/事件+定时）、目标类型（需要目标/无需目标）和事件分类筛选；「清空筛选」恢复全部。页面右上角显示规则页版本号，可用于确认浏览器已加载最新脚本。

会话事件仅投递到该事件所属且在规则中列出的会话；申请、网关状态和定时任务没有会话归属，仅投递到管理员私聊会话。载荷使用受限字段：申请类事件包含处理申请所需的一次性 `flag`，但不包含访问令牌或内部配置。事件数据不能改变权限规则。

事件历史只在内存保留启动后最近 2000 条准入记录；单次快照另受 12000 字符预算限制，完整记录不会从中截断，`includedCount` 与 `partial` 标明实际条数和是否省略。这个设置控制上游事件记录；聊天消息快照仍由下方已有的未读/最近消息参数管理。

定时任务从规则保存或桥接启动后开始计时，暂停期间不补跑，恢复后重新计时；随机范围会在每次触发后重新抽取下一次时间。保存其他规则或场景提示词不会重置未改规则的计时和冷却。页面显示下一次定时检查时间。移出白名单后停止触发。

配置和唤醒场景覆盖保存在 `state/wake-rules.json`，不进 Git；兼容读取原 `state/tool-automations.json`，自动去掉工具关联，下一次保存时写入新格式。唤醒参数通过独立的「保存唤醒参数」按钮部分更新，不覆盖二代仿真页的发送和上下文草稿。

管理接口 `GET/POST /api/wake-rules` 仅允许控制台令牌；QQ 智能体令牌一律不能访问。可单独提交 `rules` 或 `prompts`，不必重新保存另一部分。

## 上游事件日志

`state/bridge.log` 会为每个上游事件写一行类型日志，便于确认 SnowLuma 到底送来了什么：

```text
[upstream] ← message/group group:123 user:456 msg:789
[upstream] ← message/private user:456
[upstream] ← notice/group_increase group:123 user:456
[upstream] ← notice/notify/poke group:123 user:456
[upstream] ← request/friend user:456
[upstream] ← request/group/invite group:123 user:456
[upstream] ← meta_event/heartbeat good=true online=true
```

- 只记录类型、群/用户/操作者/消息 ID 与心跳健康位；不记录正文、申请 `flag`、`comment` 或文件名。
- 消息同一群/私聊 5 秒最多一行；拍一拍 1 秒；心跳 5 分钟；申请、成员变更、撤回等低频事件每条都记。
- `message_sent` 是机器人自己发出的回显，不记录。
- 未授权/未命中白名单的消息也会先记类型，再走「忽略未授权会话」逻辑，便于排查“到底有没有收到”。
- 日志仍受 `state/bridge.log` 2000 行轮转限制。

## 维护与验证

- `src/upstream-events.js`：上游事件类型日志的格式化与节流。
- `src/qq-tool-groups.js`：动作分组、工具归属、开关与参数映射。
- `src/mcp-tool-suites.js`：MCP 注册、schema 与调用适配。
- `src/tool-catalog.js`：官方目录参数校验与会话字段补齐。
- `src/tool-prompts.js` / `src/tool-protocols.js`：私有协议存储、迁移与注入。
- `src/wake-rules.js` / `src/wake-prompts.js`：独立的规则、调度和现有场景文案。
- `public/console-tools.js` / `.css`：管理界面。
- `public/console-wake.js` / `.css`：独立唤醒页面。

参数快照保留 198 个动作：基础参数取自已安装的 SnowLuma MCP 目录；1.14.22 新增的三项群分类标签参数对照本机运行时定义补齐。官方参考：[SnowLuma API](https://snowluma.github.io/zh/docs/api)。刷新脚本保留完整 schema，无法取得指定版本时不会静默降级；删除动作须显式使用 `--allow-removed`。

```sh
npm run test:tools
npm run test:audit
npm run test:mcp-servers
node scripts/build-agent-preset-patches.mjs --check
```

`test-wake-rules.mjs` 覆盖三种目标要求（会话/仅群/无需目标）、申请事件投递管理员会话且携带 `flag`、定时任务无目标、事件快照与白名单变化；`test-tool-management-http.mjs` 覆盖保存无目标规则后的实际唤醒文案；`test-tool-suites-runtime.mjs` 覆盖从私聊管理员会话调用申请处理动作。

这些回归使用内存 MCP、临时状态与假网关。它们不会向真实 QQ 发消息。
