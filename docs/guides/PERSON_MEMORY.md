# 人物印象（按 QQ 号跨群共享的长期记忆）

> 目标：让 AI **换个群也认得同一个人**——他在 A 群聊过什么、是什么脾气，到 B 群接得上。
> 实现方式与「群聊黑话」同构（候选 → 确认 → 注入），只是键从「词条」换成了 **QQ 号**。

## 1. 为什么必须是 QQ 号

现存的两套记忆都认不出同一个人：

| 记忆 | 键 | 换群后 |
| --- | --- | --- |
| `socialV2` 的 `memberImpressions` | **会话 key + 群名片/昵称** | 换群、改名 → 变成另一个人；且只在本群可见 |
| 群聊黑话（`state/slang.json`） | 词条 | 与"谁说的"无关 |
| **人物档案（本功能）** | **QQ 号** | 同一个 QQ 号在不同群里合并成一条档案 |

一个人在不同群里可以有不同群名片，因此档案里同时记 `names[]`（见过的名字，各自带出现次数）与
`groups[]`（在哪些会话里出现过）——**注入时用本群里的那个称呼**，不会把别群的群名片叫出来。

## 2. 数据与存储

- 文件：`state/persons.json`（顶层数组；`state/` 已被 ACL 收紧，与 `slang.json` 同级同权限）。
- 模块：`src/person-memory.js`（纯函数：规范化 / 上限裁剪 / 读写 / 注入块 / 提取提示词与解析）。
- 桥接接线：`src/bridge.js`（自动提取、注入、AI 工具端点、控制台 API 与控制台页面）。

一条档案的形状（简化）：

```jsonc
{
  "qq": "10001",
  "names": [{ "name": "演示群友", "count": 7, "lastAt": "..." }],
  "groups": [{ "id": "123456789", "name": "演示交流群", "count": 7, "lastAt": "..." }],
  "facts": [
    {
      "id": "…", "kind": "trait|topic|fact",
      "text": "喜欢猫，养了一只叫豆豆的橘猫",
      "status": "candidate|confirmed|rejected",
      "source": "ai|auto|manual", "count": 2,
      // 证据是群聊原文摘录 + 来自哪个会话：**只在控制台可见，绝不注入 AI 上下文**
      "evidence": [{ "key": "group:123456789", "name": "演示群友", "text": "我家猫又胖了", "time": 0 }]
    }
  ]
}
```

上限：档案 `PERSON_MAX_ENTRIES = 2000` 条、单个人 40 条事实、昵称 5 个、群 20 个、证据 5 条。
每份档案的 `content` 由程序把该人的全部有效印象和话题完整拼接生成，只去掉完全重复文本，
不调用模型改写、不对合并文本套用单条 120 字的截断。原条目、证据、来源与审核状态保留。
`contentByStatus` 分别提供已确认和候选内容；模型侧人物卡的 `content` 只含已确认内容。
新增、编辑、确认、拒绝或删除后，合并内容随事实实时更新；旧档案在桥接启动时自动补齐。
裁剪优先级：**有已确认事实的档案 > 事实多的 > 最近见过的**；单个人裁剪时**最后才动已确认的事实**。

读取失败的语义与黑话库一致：**文件不存在 = 首次运行（空库）；文件存在但读/解析失败 = 抛错并暂停写入**
（把原文另存为 `.corrupt-<时间戳>`），绝不用内存里的空数组覆盖磁盘。

## 3. 两条来源，分级生效

| 来源 | 谁写 | 生效方式 |
| --- | --- | --- |
| `ai` | 二代 AI 调 `qq_person_note` | **直接生效**（`confirmed`）：它有完整上下文，判断更准，即时可用 |
| `auto` | 桥接像黑话那样从群聊窗口自动提取（走学习会话） | 进 **候选**，等你在控制台确认后才生效 |
| `manual` | 控制台手写 | 直接生效 |

自动提取的输入窗口：群聊普通消息（跳过 `/` 命令与角色控制语），默认攒够 20 条、冷却 10 分钟触发一次，
使用独立的 **QQ 人物印象学习** 工作区（`state/person-agent/`）、学习会话与串行任务队列。
会话映射保存在 `state/person-session.json`，重启后继续使用；黑话仍使用原来的 `slang-agent/` 和
`slang-session.json`，历史对话保留。两种学习的上下文、配置与新产生的用量归属分别管理。
人物模块启用后，桥接在 DSH 就绪时自动创建或恢复这个工作区与空会话，不需要等到下一批素材。
提取结果里 **QQ 号不在本窗口说话人集合内的条目会被直接忽略**——否则模型幻觉出来的号码会凭空建出一条
属于陌生人的档案，而且会跨群注入出去。

提取范围包括本人明确表达的偏好、非敏感事实、可延续的话题与近期计划。`topic` 不要求长期稳定，
但不能把一次讨论推断成职业或永久性格；互动习惯需要多条一致表现。纯表情、辱骂、无内容感叹仍可返回空结果。
只有合法的提取结果才消费本批素材；输出格式错误或写盘失败会报错并保留素材供重试。

## 4. 注入边界（这是与"全库灌进 prompt"的关键区别）

只有**本会话里真的出现过的人**（近 24 小时在本会话说过话，或私聊里的对方）才会被注入，并且：

- 只注入 `confirmed` 的事实（候选、已拒绝都不进上下文）；
- 不注入 `evidence` 原文，也不注入其它群的**群名/群号**；
- 人数与每人条数可配（默认 6 人 × 4 条）。

注入块长这样（一代/二代都由 `withSlangContext` 统一注入，避免唤醒提示里出现两份）：

```
【人物印象】按 QQ 号跨群共享的长期印象与聊过的话题（含他/她在别的会话里留下的印象）：
- 小张（QQ 10001）：喜欢猫，养了一只叫豆豆的橘猫；最近在准备考研
使用要求：只在自然接话、避免重复提问或别踩雷时参考；不要当面复述"你在别的群说过…"…
```

AI 侧另有两个入口，取数口径同样不含证据与群名：

- `qq_person_query`：留空 = 本会话里出现过的人；传 `query`（昵称片段 / QQ 号 / 印象关键词）= **全库检索**，
  这正是"跨群印象"的用法；
- `qq_person_note`：记一条长期印象。`qq` 优先；只给 `name` 时按本会话的群名片推断，
  对不上会返回候选列表要求在重试时给出 QQ 号（不猜）。限频默认 30 次/小时/会话。

## 5. 隐私过滤（写之前就拦）

`looksSensitiveFact()` 会丢弃含邮箱、中国大陆手机号、15–19 位长数字（卡号/单号）、身份证号、
以及「密码/验证码/口令/密钥/token/api key/身份证号/银行卡号/家庭住址」的文本。
自动提取的提示词里也明令禁止记录隐私、他人负面八卦、外貌评价、政治宗教倾向。

理由：这是一个**会跨群注入给模型**的库。往里面放手机号，等于让它在另一个群里有机会说出来。

## 6. 配置（`config.json` → `personMemory`）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关（关掉后不提取、不注入、AI 工具 403） |
| `autoExtract` | `true` | 是否从群聊自动提取（结果进候选） |
| `extractMinMessages` | `20` | 触发提取的最少消息数 |
| `extractCooldownMs` | `600000` | 同一会话的提取冷却 |
| `inject` | `true` | 是否把印象注入 AI 上下文 |
| `injectMaxPersons` | `6` | 每次最多注入几人 |
| `injectMaxFactsPerPerson` | `4` | 每人最多注入几条 |
| `notePerHour` | `30` | AI 用 `qq_person_note` 写印象的限频 |
| `learnerPreset` | `''` | 人物学习专用 preset（空则跟随 `agentPreset`，不使用黑话 preset 配置） |
| `workspaceTitle` | `QQ 人物印象学习` | 人物学习工作区标题 |

工具开关在 `socialV2.tools`：`personQuery` / `personNote`（默认都开；改完需重启 DSH 才刷新工具 schema）。
两个开关在控制台「人物印象」页保存（走 `/api/persons/config`），**刻意不放进「二代仿真」页**——
那个页面的提交载荷有「改版前控制台」的回归基线，加字段会让基线失真。

## 7. 控制台

「人物印象」页（导航第 7 项）三个标签页：

- **人物**：QQ / 昵称 / 出现过哪些会话 / 已确认数 / 候选数 / 最近活跃；可加印象、整人删除；
- **候选印象**：自动提取的结果，勾选后批量确认 / 拒绝 / 删除，或一键清空候选；
- **已确认印象**：编辑内容与类型、撤回为候选、删除、清空；
- 底部：手动记人、参数区（含两个 AI 工具开关）。

三个标签均按人集中展示合并内容；候选与已确认标签中，同一人的原条目、证据和审核按钮收在详情中。

**证据原文与来源会话只在这个页面可见**——这是刻意的：原文留在控制台给管理员判断，
不进任何 AI 上下文。

「立即学习一次」等待分析完成，显示实际分析消息数、新增与更新候选数；手动操作不受自动提取的
消息数门槛、冷却和 `autoExtract` 开关限制，仍遵守功能总开关与会话允许范围。重启后学习窗口为空时，
可以使用二代模式已持久化的本群最近消息。没有素材、DSH 未就绪或结果格式错误会明确提示。

## 8. 排障

| 现象 | 先看 |
| --- | --- |
| 候选一直是空的 | `personMemory.enabled` / `autoExtract` 是否关；群聊消息是否达到 `extractMinMessages`；日志里 `人物档案提取：…`；也可在页面上点「立即学习一次」 |
| AI 聊天时看不到印象 | 是不是没有 `confirmed` 的事实（候选不注入）；当前会话里那个人是否真的说过话；`inject` 是否为 false |
| 改了却没生效 | 页面顶部的统计条会显示 **只读降级**（`state/persons.json` 读取失败时暂停写入）；修好后重启桥接 |
| AI 写印象被拒 | 返回里会说明：内容疑似隐私、限频、或"无法确定属于谁"（此时按返回的 `candidates` 传明确 QQ 号重试） |
| 想清掉跨群记忆 | 页面上「清空全部已确认」（AI 会立即失去这些印象）或整人删除 |
